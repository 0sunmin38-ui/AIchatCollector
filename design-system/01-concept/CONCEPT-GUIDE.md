# 컨셉 & 톤앤매너 가이드

> 디자인 시스템의 첫 단계: 서비스의 성격과 분위기를 정의합니다.

---

## 왜 컨셉이 먼저인가?

```
컨셉 → 색상/폰트 선택 기준
     → 컴포넌트 스타일 결정
     → 전체 일관성 유지
```

"친근한 서비스"와 "전문적인 서비스"는 같은 파란색이라도 다른 톤을 씁니다.

---

## 정의해야 할 항목

### 1. 타겟 사용자

| 질문 | 예시 답변 |
|------|-----------|
| 누가 쓰나요? | 개발자, 디자이너, 기획자 |
| 연령대는? | 20-40대 |
| 기술 수준은? | 중급 이상 |
| 주 사용 환경은? | 데스크톱 > 모바일 |

### 2. 브랜드 성격 (형용사 3-5개)

**선택지 예시:**

| 축 | 좌측 | ← → | 우측 |
|-----|------|-----|------|
| 온도 | 따뜻한 | ● | 차가운 |
| 무게 | 가벼운 | ● | 무거운 |
| 태도 | 친근한 | ● | 전문적 |
| 스타일 | 장식적 | ● | 미니멀 |
| 움직임 | 정적 | ● | 동적 |

**조합 예시:**
- 토스: 따뜻한 + 가벼운 + 친근한 + 미니멀
- 노션: 차가운 + 가벼운 + 전문적 + 미니멀
- 당근: 따뜻한 + 가벼운 + 친근한 + 약간 장식적

### 3. 핵심 감정/인상

서비스를 쓸 때 사용자가 느꼈으면 하는 감정:

```
예시:
- "신뢰할 수 있다"
- "쉽고 간단하다"
- "정돈되어 있다"
- "나를 도와준다"
```

### 4. 경쟁/참고 서비스

| 서비스 | 좋은 점 | 다르게 할 점 |
|--------|---------|--------------|
| A | 깔끔한 레이아웃 | 색상이 너무 차가움 |
| B | 친근한 톤 | 너무 복잡함 |

## CONCEPT.md 템플릿

```markdown
# [서비스명] 디자인 컨셉

## 타겟 사용자
- 주 사용자:
- 연령대:
- 기술 수준:
- 주 환경: 데스크톱 / 모바일 / 둘 다

## 브랜드 성격
- [형용사 1]
- [형용사 2]
- [형용사 3]

## 핵심 감정
사용자가 느꼈으면 하는 것:
> "[한 문장으로 표현]"

## 시각적 방향

### 색상 방향
- 주 색상 계열: [파랑/초록/따뜻한 계열 등]
- 느낌: [차분한/활기찬/신뢰감 있는]

### 형태 방향
- 모서리: [둥근/각진/혼합]
- 여백: [넉넉한/촘촘한]
- 밀도: [정보 많이/여유있게]

### 톤 방향
- 텍스트 톤: [격식체/반말/친근한 경어]
- 아이콘: [라인/면/혼합]

## 참고 서비스
1. [서비스명] - [참고할 점]
2. [서비스명] - [참고할 점]

## 하지 않을 것 (Don'ts)
- [피할 스타일 1]
- [피할 스타일 2]
```

## AI와 작업할 때

### 프롬프트 예시

```
"이 서비스는 AI 대화 수집 도구야.
타겟은 개발자와 연구자.
노션처럼 깔끔하지만 조금 더 따뜻한 느낌을 원해.
컨셉을 정리해줘."
```

### 컨셉 확정 후 다음 단계

컨셉이 정해지면 → `02-tokens/`로 이동해서 토큰 설정

```
"01-concept/CONCEPT.md를 참고해서
이 컨셉에 맞는 색상 팔레트를 제안해줘"
```
