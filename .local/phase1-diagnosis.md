## 1. 크롤링이 실제로 하는 일

### 1-1. 설정은 어디서 읽나

`lib/paths.mjs:57-61` `confFile()` 은 **데이터 폴더의 파일을 코드 옆 파일보다 먼저** 쓴다.
지금은 iCloud 의 `config.json` · `taxonomy.json` · `glossary.json` 이 실제 설정이다.
코드 옆 `config.json` 과 내용은 현재 같지만, 앞으로 어긋나면 코드 쪽을 고쳐도 반영되지 않는다.

### 1-2. 수집 단계 (`lib/crawler.mjs:53-257`)

**1단계: 목록** (`:99-131`)
- job 의 `targets` 마다 목록을 `pages` 쪽만큼 넘긴다. 모드는 `all`(전체글) · `recommend`(개념글) · `search`(검색) 세 가지다.
- `@개념:xxx` 검색어는 사전(glossary)의 표면형으로 펼친다. 한 글자짜리는 빼고, 최대 60개까지만 쓴다 (`:11-32`).
- 이 단계에서 버리는 것은 **공지(`is_notice`)** 와 **기간 밖 글**(`--since/--until` 을 줬을 때)뿐이다 (`:111-112`). 키워드나 말머리로 거르는 규칙은 없다.

**2단계: 본문과 댓글** (`:133-212`)
- 후보는 이번 목록에서 본 글과 저장소에 제목만 남은 글이다 (`:138-147`).
- 본문이 이미 있으면 다시 받지 않는다. `onlyRecommend` 면 개념글 출신만 후보가 된다 (`:149-155`).
- 상한 `maxPosts` 중 `freshShare`(기본 0.5)만큼은 최신순으로, 나머지는 추천순으로 고른다 (`:159-175`).
- 댓글은 100개씩 **최대 10쪽(1,000개)** 까지 받는다 (`:196`).

**3단계: 저장** (`:214-255`)
- `dedup` 이면 제목·추천·댓글수가 그대로인 글은 다시 쓰지 않는다 (`:221-231`). 기간 수집일 때만 기본으로 켜진다.
- `posts/YYYY-MM.jsonl` 에 줄을 덧붙이고, `runs/<runId>.json` 에 실행 기록을, `state.json` 에 커서를 남긴다.

## 2. 분류가 지금 어떻게 되나

**구조** (`taxonomy.json`): 카테고리 7개가 **한 축**에 있다.
위젯·상태창 / OOC / 지침 / 이미지 프롬 / 그깎·작태 / 확장 / 홍보 + 기타.
카테고리마다 신호 종류(`tag` `titleStrong` `title` `head` `body` `neg`)별로 가중치와 단어 목록을 둔다.
`@개념:xxx` 는 사전을 참조한다.

**판정** (`lib/classify.mjs:49-97`)
- 카테고리마다 점수를 매겨 **1등 하나만** 고른다. 1등 점수가 `threshold`(4)보다 낮으면 '기타'가 된다.
- 2등도 기준을 넘으면 `also` 에 담기지만, 화면에서는 쓰지 않는다. 보이는 글 중 **29건이 두 번째 분류를 잃는다.**
- 본문은 앞 12,000자만 본다. **댓글은 보지 않는다.**

**수동 수정** (`lib/labels.mjs`): `labels.json` 에 글번호마다 카테고리 **하나**를 저장하고, 자동 분류보다 우선한다. 현재 4건이다.
서재의 `tags`(`bookmarks.json`)는 이와 별개로 자유 태그이고, 서재 글에만 붙는다.

### 3-3. 버그로 안 보이거나 틀리게 보이는 것

1. **서재 이미지가 로컬 뷰어에서 안 뜬다.** `serve.mjs:173` 은 이미지 경로를 `코드폴더/data/...` 로 고정해 두었는데, 실제 데이터는 iCloud 에 있다. 확인해 보니 그 경로가 존재하지 않는다. 그래서 보존한 이미지 43장이 전부 404 로 나간다. `scrub.mjs:17` 도 같은 방식으로 경로를 고정해 두어 데이터 폴더를 못 찾는다. `run.sh:10` 의 로그도 코드 쪽에 쌓인다.
2. **댓글 날짜의 연도가 틀린다.** `lib/parse.mjs:47` 은 댓글 날짜가 기준일(글 날짜)보다 7일 넘게 뒤면 작년으로 돌린다. 그래서 몇 달 뒤에 달린 댓글이 1년 전 날짜가 된다. 댓글 27개(글 14건)가 이 상태다.
3. **말머리가 중복되어 저장된다.** 목록에서 파싱한 `headtext` 가 `🎬콘텐🎬콘텐츠` 처럼 저장된 글이 105건이다. 본문 쪽 값은 정상이다. 목록 HTML 의 말머리 칸에 축약형과 전체형이 같이 들어 있는 것으로 보이지만 확인하지는 않았다.
4. 사전에 `옾` 이 오푸스의 별칭으로 있는데도 `"옾 쓰다가…"` 를 넣으면 감지하지 못한다. 한 글자 표면형을 건너뛰는 규칙 때문으로 보이지만 확인하지는 않았다.

## 5. 2단계 설계 전에 정해야 할 것

1. **제목만 있는 983건을 어떻게 할까.** ① 화면에 '제목만' 으로 같이 보인다 ② 본문을 마저 받는다(백로그 소진. 하루 60건이면 16회 이상) ③ 제외 규칙에 걸리는 것은 지운다. 여러 개를 함께 고를 수 있다.
2. **축 목록.** 제안: `platform`(서비스) · `model`(대화 모델) · `imagegen`(그림 모델: nai, pixai …) · `topic`(지금의 7개 카테고리) · `type`(말머리 기반: 잡담·질문·리뷰·정보·제작·그림). 더하거나 뺄 축이 있는지.
3. **제외 기준의 예.** 예를 들어 "홍보 말머리 전부", "특정 플랫폼 홍보글" 처럼 지우고 싶은 글의 예를 2~3개 들어 주면 규칙 형식을 거기에 맞춘다.
4. **버그 3-3 의 1·2번은 2단계를 기다리지 않고 바로 고쳐도 될까.** 둘 다 작고 독립적이다.
